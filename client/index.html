请求处理流程

①

浏览器请求

用户访问页面或调用 API，所有请求统一到达 Nginx。

②

Nginx 路由分发

静态文件（client/）直接返回；PHP 请求通过 fastcgi_pass 转发；Node 请求通过 proxy_pass 转发。

③

后端处理

PHP 执行 CRUD 操作写入 MySQL；Node 启动 Puppeteer 无头浏览器爬取抖音数据。

④

响应返回

JSON 数据返回前端，JavaScript 动态渲染到页面。

设计亮点

六大核心设计决策，兼顾工程规范与开发效率

🏗️

前后端分离架构

// decoupled

前端纯静态 HTML/CSS/JS，零构建流程、零框架依赖。PHP 和 Node.js 独立部署，Nginx 统一路由分发，低耦合高内聚。

Nginx→Static|PHP-FPM|Express
⚙️

分层配置管理

// config-layers

四套配置独立管理，杜绝敏感信息硬编码：database.php（MySQL 连接）、.env（SMTP 凭据，不进版本控制）、node_conf.json（监听端口 + Chrome 路径）、accounts.json（爬虫数据落盘）。

database.php.envnode_conf.jsonaccounts.json
📋

招聘三段式幂等提交

// idempotent-form

严格三步顺序执行，保证数据一致性：① 手机号查重 → ② 数据入库（phone UNIQUE 约束） → ③ 邮件通知。步骤 ② 成功才触发步骤 ③，避免无效邮件骚扰。

🔄

抖音数据双模式

// dual-mode

手动模式：请求触发 Puppeteer 实时爬取，适合按需查看。定时模式：node-cron 每 2 小时自动爬取并落盘为静态 JSON，前端直接读取，零延迟响应。双模式共享 cookie 配置，支持 /api/update-cookie 运行时热更新。

🧩

ConfigManager IIFE 单例

// singleton-pattern

前端唯一的配置加载入口。IIFE 模块模式实现缓存命中直接返回、重复请求自动等待首次完成、强制刷新支持。避免全局变量污染，所有页面通过统一接口获取后端 API 地址。

const ConfigManager = (function() {
  let cachedConfig = null;
  let isLoading = false;
  // 缓存命中 → 直接返回
  // 重复请求 → 等待首次完成
  // 强制刷新 → force=true
  return { loadConfig, getAPIBase, getConfig };
})();

部署运维

pm2 + Nginx + cron，轻量化生产部署方案

①

Nginx 静态托管

client/ 目录作为 web root，PHP 通过 fastcgi_pass 反向代理，Node 通过 proxy_pass 转发至本地端口。

②

pm2 进程守护

Node.js Express 服务由 pm2 管理，支持自动重启、日志轮转和资源监控，保证 7×24 稳定运行。

③

cron 定时任务

node-cron 每 2 小时自动触发抖音数据爬取，结果落盘 accounts.json，前端读取零延迟。

④

安全措施

SMTP 凭据 .env 不进版本控制；Node 服务仅监听本地回环地址；MySQL phone 字段 UNIQUE 约束防重复提交。
